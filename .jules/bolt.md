## 2024-05-24 - Avoid duplicate organization queries in tenant access
**Learning:** `getWorkspaceExperienceBySlug` calls `organizations.findBySlug` unconditionally. In `resolveTenantAccess`, when resolving from existing memberships (`listByIds`), we already fetched the full `Organization` object, but we still call `getWorkspaceExperienceBySlug(organization.slug)`, forcing a redundant database lookup for the same org. The function `compileWorkspaceExperience` accepts an optional `organization` object to skip this query.
**Action:** Replace `getWorkspaceExperienceBySlug(organization.slug)` with `compileWorkspaceExperience({ slug: organization.slug, organization })` in `resolveTenantAccess` when the `organization` is already fetched, to avoid an N+1/redundant query per login. Be careful to check the return types!
