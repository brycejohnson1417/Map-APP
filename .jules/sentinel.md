## 2024-10-08 - Protect against XSS in Email Previews with srcDoc iframe
**Vulnerability:** Found `dangerouslySetInnerHTML` being used to render an email preview HTML string within `components/accounts/ppp-savings-panel.tsx`. Although DOMPurify was in use, dynamically rendering user-controlled or rich-text HTML using `dangerouslySetInnerHTML` presents an inherent XSS risk, especially in the context of email body contents.
**Learning:** Even sanitized HTML strings pose a risk if directly injected into the DOM, as edge cases in the sanitizer or future changes could expose vulnerabilities. Furthermore, direct injection leaks styles from the application to the preview or vice versa.
**Prevention:** Always use a sandboxed `<iframe>` with the `srcDoc` attribute to render dynamic HTML content, especially for previews like emails. Use `sandbox="allow-popups allow-popups-to-escape-sandbox"` to permit basic interaction (like clicking links) while omitting `allow-scripts` and `allow-same-origin` to ensure an isolated browsing context. To apply styling correctly to the contents of an iframe, an inline `<style>` tag should be manually injected.
